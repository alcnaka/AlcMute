# v0.3.0 設計・検証記録（公開前）

このブランチは実装レビュー用です。正式Release・タグ・pushは行っていません。
Windows上のビルド／APIテストと、インストール操作を伴うE2Eを区別します。

## 配布と起動

- 既定ビルドはPortable、`--features installer`だけがInstallerです。ファイル名・作業ディレクトリで推測しません。
- Inno SetupのAppIdは`{D7267BA5-A7BD-46DB-A39F-47E9F7843CF6}`で固定。
- インストール先はユーザーのLocalAppData配下。新規は空の専用フォルダー、更新は登録済みフォルダーを使用します。
- `InstallDir`とInnoのアンインストール登録・実行ファイルの製品情報・実行パスを照合します。未管理のInstaller EXEも自動起動を操作できません。
  製品情報は固定の英語コードを仮定せず、リソース内のTranslationを参照します。配布EXEの検証専用起動でもこのネイティブ読み取りを確認します。
- 手動の二重起動は既存Mutexで検出し、現在のユーザーSIDだけを許可した名前付きイベントで設定画面を要求します。
  同じDACLの小さな共有メモリでPIDを渡し、クライアントから前面表示権限を渡します。要求はMutexで直列化します。
- IPC待機用スレッドを1本使用します。カーネル待機であり、常時ポーリングは追加していません。
- `--background`は初期設定画面を抑制します。既に起動中の場合も設定画面を開きません。
  手動起動時は従来の`show_settings_on_startup`を尊重します。

## 自動起動

- PortableはUIだけでなくRust APIでも新規登録・変更・削除を拒否します。設定に古い`autostart = true`があっても無効です。
- 保存・初期化はPortableでRun APIを呼びません。通常起動で`migrate_startup()`を実行しません。
- 状態はRun登録とWindowsのStartupApprovedを読み、TOMLへは書き戻しません。
- 移行はInnoからの`--install-migrate`のみ。旧AlcMuteを終了してから実行します。
- ファイルの製品情報、既知の登録名と設定パス、既知のPoCパスを組み合わせて識別します。ファイル名だけでは削除しません。
- 元のRun値・型・生バイトとStartupApprovedを`startup-migration-backup.txt`（JSON行）に同期保存してから変更します。
- 正規の1登録を作り検証した後に識別済み旧登録を削除します。失敗時は元の値を復元します。
- 明示的なWindows無効化を維持し、判定不能なStartupApproved状態では移行を中止します。
  無効なRun値を通常保存で消してWindowsの画面から再有効化できなくなることも避けます。
- `--data-dir`を引き継ぎ、旧既定パスだけを新しい既定パスへ正規化します。
- スタートアップフォルダーの`.lnk`や、識別不能な他方式の登録は自動削除しません。必要なら手動確認します。
- アンインストールは実行パスが自身と一致するRun値だけ削除します。設定と旧Portable本体は削除しません。

## 更新と互換性

- 外部HTTPSは専用ureq/Rustlsクライアントを使用し、OSCQueryのループバックHTTP設定と分離。
- 起動時1回／手動時のみ確認。手動確認も60秒未満の連打を抑制し、常駐タイマーは追加しません。
- TLS検証、接続5秒・要求30秒、JSON 2MiB、Setup 128MiB、チェックサム64KiBの上限。
- stable SemVer、canonical tag、リポジトリURL、厳密なAsset名、uploaded状態、サイズ、SHA-256を検証。
  リダイレクト先もGitHubの既知のHTTPSホストに限定し、資格情報入りURL・不正ポートを拒否。
- Installerの更新はユーザーの確認後のみ。現在ユーザー専用DACLの一時フォルダーへダウンロードします。
- 別コピーのヘルパーが公式マニフェストを再取得して再検証し、Setupファイルを変更／削除不可で開いたまま実行します。
  親PIDと実行パスを確認して正常終了を待ち、既存インストール先へSetupを実行します。
- 更新直前の旧EXEも保全。終了コード、アンインストール登録と実EXEのバージョンを確認してバックグラウンド再起動します。
- Setupの失敗時はログ・保全ファイルを残して既存アプリの再起動を試みます。完全な自動ロールバックの保証はありません。
  ディスク障害・途中電源断などは実機検証と手動再インストールが必要です。
- SHA-256は配布元自体の侵害への署名の代わりではありません。署名付きマニフェストとコード署名は将来対応です。
- 更新設定は`updates.toml`に分離。従来6項目の`settings.toml`に新しいキーは追加しません。
  v0.2.2へ戻す場合は旧EXEを手動配置し、Installerの自動起動を先に解除してください。旧版は`--background`に対応しません。
- 保存は検証→pending同期保存→正常な旧設定の`.bak`確保→Windowsの置換API。
  復旧は確認を得てから実行し、破損原本を別名で保全します。壊れたバックアップからの初期化はしません。

## 自動テストとビルド

テストのRun／StartupApprovedは、テストプロセス固有の
`HKCU\Software\AlcMute\Testing\<PID>`に固定されます。実ユーザーのRunキーを書き換えません。

- 既存のOSCパルス・状態・キュー・ホットキー・保存失敗復旧・ページ分割テストを維持。
- Portableの旧autostart=true読み込み、保存・初期化、直接API拒否、Run値不変。
- 既知の旧登録・PoC・重複統合、OFF維持、Windows無効化維持、無関係な登録の保持、再実行、アンインストール時の所有確認。
- IPCの往復、同時要求、待機スレッドの正常停止。
- バックアップ復旧と破損原本保全、壊れたバックアップ拒否。
- SemVer／Draft／Pre-release、欠落Release、APIエラー、不正URL・サイズ・ハッシュ、更新設定の分離。
- ライセンス展開結果と元ファイルの完全一致、ライブラリ別・UTF-8ページ分割。
- 実GitHub HTTPSテストは通常CIでignore。明示的に指定して接続テストを実施。
- `verify-artifact.ps1`で両形式のVERSIONINFO、配布種別、16/24/32/48/256pxアイコン、MIT本文、ライセンス展開、開発用エンドポイント非混入を検証。
- Inno SetupコンパイルとPortable ZIP生成・SHA-256算出を実施。通常push/PRはReleaseを作らず、タグ時も下書きに限定。

## 公開前に必要なWindows E2E（未実施）

テスト用WindowsユーザーまたはVMで、次を確認してください。

1. 新規／標準／変更先へのインストール、ショートカット、インストール済みアプリ一覧。
2. 同じAppIdの更新とインストール先保持、Program Files・設定フォルダー・非空の未管理フォルダーの拒否。
3. 実際の旧Portable ON/OFF・Windows無効化・カスタムdata-dir・複数登録を作った移行。
4. 実機での自動起動ON/OFF、ログイン時非表示、Portableのグレーアウトと説明。
5. 隠れた／最小化した設定画面の二重起動による復元・前面化。異なるユーザーからIPC不可。
6. オフライン・プロキシ・API制限時にもOSCとホットキーが継続すること。
7. 正規の新しいstable Releaseを使う、許可→検証→終了→Setup→再起動のE2E。
8. Setup失敗・ディスク不足・終了タイムアウト時の旧版保持／保全ファイル／ログと再試行。
9. アンインストール時の自動起動解除、設定保持、他アプリ／旧Portableの登録と本体の保持。
10. 実VRChat、左右修飾キー・通常キー同時押し、トレイ、混在DPI、About表示。

正式Releaseの公開、GitHub Actions上の実行、Windowsログイン・実インストール操作は、この作業では実施していません。

## 性能

通常起動ではライセンスを展開しません。Aboutを一度開いた後はキャッシュします。
EXEサイズは配布物の実測を別途追記します。起動時間、Working Set、Private Bytes、アイドルCPUは未測定です。
実行中のv0.2.2を終了したり差し替えたりしていません。
